# 069 — Simulator crash after Dependabot RNGH 3.x / RN 0.86.2 bumps

**Area:** runtime / deps · **Priority:** high · **Effort:** S · **Status:** done

## Problem

On `develop` after Dependabot landed `react-native-gesture-handler` **3.1.0** and `react-native` **0.86.2** (plus React **19.2.8**), the iOS simulator app aborts shortly after launch on the Hermes / Fabric JS thread (`EXC_BREAKPOINT` / `SIGABRT` / heap freelist abort).

Metro client log with RNGH 3.1.0:

```
[TypeError: undefined is not a function]
Code: NativeProxy.ts
> return RNGestureHandlerModule.installUIRuntimeBindings();
  installUIRuntimeBindings (react-native-gesture-handler@3.1.0 …/v3/NativeProxy.ts:65)
```

Pinning only RNGH back to 2.32 was **not** enough: Fabric still aborted allocating `ShadowNodeFamily` / cloning Yoga children (malloc freelist / `EXC_BAD_ACCESS` on JS thread) while on RN 0.86.2.

`npx expo install --check` for Expo SDK 57 expects:

- `react-native-gesture-handler` **~2.32.0**
- `react-native` **0.86.0**
- `react` / `react-dom` **19.2.3**

## Proposal / resolution (2026-07-28)

1. Pin `react-native-gesture-handler` to `~2.32.0`.
2. Pin `react-native@0.86.0`, `react@19.2.3`, `react-dom@19.2.3`.
3. `pod install` + rebuild the iOS sim binary + Metro `--clear`.
4. Block Dependabot major/patch bumps that fail `expo install --check` until SDK documents support.

Clean Metro alone was not sufficient — native binary and JS must match Expo’s expected set.
